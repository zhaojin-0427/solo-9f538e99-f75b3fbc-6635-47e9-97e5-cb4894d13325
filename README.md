# 集装箱过闸记录查询（港区）

Flask + SQLite 的查箱网页：按批号上传/更正过闸流水 CSV，按箱号查询命中行，
并可为每份现用原件构建 ≤ 2 KiB 的布隆过滤器，查询时跳过不可能命中的批次原件。
闸机只能重导出错时段时，可在首页走**按时段更正**：选批号与 UTC 起止时刻查看该段，
再上传同格式 CSV 整段替换，区间外流水保留。

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据库保存在命名卷 `gate-data`（容器内 `/data/gate.db`），重启不丢数据。

### 本地开发

```bash
python3 -m venv .venv && .venv/bin/pip install -r app/requirements.txt
DATABASE_PATH=/tmp/gate.db .venv/bin/python app/app.py
```

## 使用说明

- **上传 / 更正**：首页填写批号并选择 CSV。同批号再次上传即**整份替换**
  （版本号 +1，旧行、旧过滤器在一个事务内作废）。任一数据行非法则整份拒绝。
- **按时段更正（只重导出错时段）**：首页“按时段更正”选**现有批号**与 UTC 起止时刻，
  先查看该段记录（左闭右开 `[起点, 终点)`：起点计入、终点不计入，时刻须带 `Z`/`+00:00`），
  再在查看页上传同格式 CSV 整段替换。
  - 替换行时刻必须全部落在所选时段内，**含越界行整份拒收**。
  - **只有表头的 CSV** 表示清空所选时段；仅含空行的文件仍视为无效。
  - 区间外的最新流水原样保留，合并后全批仍限 **5000 行**，超限整份拒绝。
  - 提交时按**箱号 + UTC 时刻逐组核对条数（忽略行序）**，比较页面所见与库中最新区间内容；
    时段已变则拒绝并提示重新查看。即使批次已升版，只要所选时段未变，旧查看凭证仍可在最新版上合并。
  - 成功即批次升版、旧布隆过滤器同时失效，查箱随即读到合并结果；
    失败的提交不改动任何流水或索引（全部校验在写事务外/回滚前完成）。
- **CSV 格式**：两列 `箱号,UTC过闸时刻`，UTF-8（可带 BOM），数据行 1~5000 行
  （时段更正的替换文件本身也不得超过 5000 行；只有表头的更正文件为 0 数据行）。
  - 箱号：字母/数字/`.-_`，1~64 字符，录入与查询统一去空格并转大写。
  - 时刻：ISO 8601。带时区（如 `+08:00`、`Z`）归一化为 UTC；无时区按 UTC 处理。
  - 表头：仅当第一行第二列不是合法时刻、且第一列是常见表头词（`箱号`、`container` 等）
    或不符合箱号格式时，第一行按表头跳过；否则按数据行严格校验。
- **查询**：按箱号列出命中行（批号、版本、行号、UTC 时刻），以及
  **实际扫描过的批次**和被同版过滤器**跳过的批次**。
- **建立布隆过滤器**：批次列表逐批点击，后台构建（≤ 2 KiB）。
  同版过滤器判定箱号不存在 → 跳过该批原件；否则逐行核对原件。

## 并发与一致性设计

| 要求 | 实现 |
| --- | --- |
| 一次查询使用同一已提交状态的原件和索引 | 整个查询包在**一个读事务**里（WAL 快照）：批次版本、过滤器、原件行三者一致；期间的更正/建索引对本查询不可见 |
| 建索引时同批照常更正、查询 | 过滤器在后台线程构建；构建只读快照、计算在内存，提交是短写事务；更正与查询不因此阻塞 |
| 迟到的旧索引不得覆盖新版索引 | 构建提交是**条件更新**：`UPDATE batches ... WHERE id=? AND version=? AND building_version=?`；批次已前进则更新 0 行，旧过滤器直接丢弃不入库 |
| 构建失败仍可查原件 | 失败仅把批次标记为 `failed`；查询只在 `filter_version == 当前版本` 且过滤器就绪时才用过滤器，否则一律回退逐行扫描原件 |
| 更正时整份替换 | 单写事务内：版本 +1 → 删旧行 → 插新行 → 清旧版本过滤器 |
| 按时段更正的乐观并发控制 | 查看页对区间内容按 (箱号,UTC时刻) 分组计数生成 SHA-256 指纹（隐藏字段）；提交在 `BEGIN IMMEDIATE` 写事务内重算最新区间指纹比对，不一致即回滚并要求重新查看。批次升版但区间未变时凭证仍有效，合并在最新版上进行，区间外流水保留 |
| 时段更正失败不留痕 | 格式/越界/超限/指纹等校验均在写事务外或回滚前完成；任何失败都不会改动 `rows`、`batches` 与 `filters` |

数据表：`batches`（批号、版本、行数、过滤器指针）、`rows`（按批号+版本存原件行）、
`filters`（按批号+版本存过滤器，blob ≤ 2048 B）。

## HTTP / JSON 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 首页（批次列表、上传、按时段更正与查询表单） |
| POST | `/batches` | 上传/整份更正，表单字段 `batch`、`file` |
| GET | `/segment?batch=<批号>&start=<UTC>&end=<UTC>` | 时段更正入口；校验后 302 到规范查看页 |
| GET | `/batches/<批号>/segment?start=<UTC>&end=<UTC>` | 查看 `[start,end)` 内记录，返回含区间指纹的更正表单 |
| POST | `/batches/<批号>/correction` | 提交时段整段替换；表单字段 `start`、`end`、`digest`、`file` |
| POST | `/batches/<批号>/filter` | 后台构建过滤器；表单字段 `delay`（秒，≤10）为**测试钩子**，模拟慢构建 |
| GET | `/query?container=<箱号>` | 查询结果页；加 `&format=json` 返回 JSON |
| GET | `/api/batches` | 批次状态 JSON（版本、过滤器状态等） |

## 已知限制 / 未完成

- 无登录鉴权与 CSRF 防护，按内网工具定位；对外部署需加网关或补认证。
- 使用 Flask 内置服务器（threaded），适合科室级并发；更大规模可换 gunicorn（单 worker 多线程即可，构建互斥由数据库保证）。
- 布隆过滤器有误报（5000 行满批、2 KiB 上限下约 20%）：误报只会多扫一个批次，不影响结果正确性；绝不会漏查（无假阴性，已测）。
- 未提供批次删除界面（可整份覆盖）；旧版本原件行随更正即删，不留历史。
- 时段更正的区间指纹是页面隐藏字段，按内网工具定位未做签名防伪：伪造凭证只会以
  “与库中最新区间不一致”被拒，不会写入非法数据；对外部署需补认证/CSRF。
- 本仓库交付环境无 Docker 守护进程，`docker compose` 未实际启动过；Compose/Dockerfile
  已经静态检查，镜像内启动命令 `python app.py` 与本地冒烟验证的路径完全一致，
  且本次新增代码仅使用标准库与既有 Flask 依赖，镜像构建内容无变化。
